1. 한 장 그림

컨테이너의 주인은 Docker Engine. VS Code / periscribe-agent 는 "띄워줘"라고 부탁하는 진입구일 뿐. Claude Code 는 컨테이너 안 평범한 CLI.

3. 누가 컨테이너를 관리하나 — Engine이지 VS Code가 아니다

대시보드/docker ps의 컨테이너 ID는 Engine이 소유. VS Code를 꺼도 컨테이너는 계속 산다. (VS Code가 띄운 이미지 이름은 vsc-…로 시작 — 그 흔적.)

4. 호스트 쉘 vs 컨테이너 쉘 — Claude는 "어느 무대"에서 도는가

같은 claude CLI라도 어느 환경에서 실행되느냐가 🖥 vs 🐳를 가른다. VS Code "Reopen in Container"는 통합 터미널을 호스트 쉘에서 컨테이너 쉘로 바꿔치기한다.

5. 두 가지 진입 방법

격리·수집 메커니즘은 동일(워크스페이스만 마운트 · --cap-drop=ALL · 경로 첫 세그먼트=container_id). 차이는 "어떻게 들어가느냐"뿐.

VS Code "Reopen in Container"periscribe-agent 런처 (권장)
진입구IDE(에디터 창)터미널 한 줄 / exe 더블클릭
무게VS Code Server를 컨테이너에 설치없음 (바로 docker run -it)
띄우는 법확장이 .devcontainer/ 자동 처리periscribe-agent <폴더> --name <id>
인증컨테이너 안에서 매번 별도첫 1회 /login → 호스트에 영속(재로그인 불필요)
이미지vsc-… (자동)periscribe-agent:latest (임베드 Dockerfile 1회 빌드)
수집동일 — bind → Collector → 🐳
periscribe-agent 는 컨테이너 ~/.claude 전체를 호스트 container_root/name에 bind → 로그인 토큰이 호스트에 남아 재로그인 불필요, 그 아래 projects/… transcript는 그대로 Collector가 수집. (devcontainer는 ~/.claude/projects만 bind.)

6. 라이선스 — 걸리는 건 "컨테이너"가 아니라 "Docker Desktop"뿐

컨테이너 기술/엔진 자체는 무료. 약관은 Docker Desktop이라는 제품에만 적용된다.

Docker Desktop (2026 기준)

대상비용
개인 · 학생 · 비상업 OSS · 직원 250명 미만 그리고 연매출 $1,000만 미만 소기업무료 (Docker Personal)
직원 250명 이상 또는 연매출 $1,000만 이상유료 (Pro/Team/Business, 인·월 $9~24)

→ 개인/소규모면 Desktop도 무료. 큰 회사 PC에 배포할 때만 그쪽의 라이선스 부담이 생긴다.

Desktop 없이 같은 컨테이너를 쓰는 무료 대안

런타임라이선스비고
Docker Engine (WSL2에 직접)Apache 2.0 (무료)Desktop 없이 dockerd만. 데몬 직접 관리(WSL2 systemd로 수월).
Podman / Podman DesktopApache 2.0 (무료)데몬리스·루트리스. docker와 CLI 호환. 상업 무료.
Rancher Desktop오픈소스 (무료)내부 moby/containerd. GUI도 무료.
설계 방침: periscribe-agent 는 PATH의 docker(→ 향후 podman)를 자동 감지 → Desktop이든 Engine이든 Podman이든 런처 코드 변경 없이 동작. 라이선스 결정을 미뤄도 되고, 갈아타도 공짜로 따라온다.

7. 용어 · 격리 한계

용어뜻
이미지 vs 컨테이너이미지=템플릿(읽기전용), 컨테이너=이미지로 띄운 실행 인스턴스. 여럿이 한 이미지 공유.
bind mount vs volumebind=호스트 특정 경로를 컨테이너에 직결(transcript 유출·로그인 영속에 사용). volume=Docker 관리 저장소.
--cap-drop=ALL컨테이너 프로세스의 리눅스 capability 전부 제거(권한 최소화).
container_rootCollector가 "컨테이너 세션"으로 watch하는 루트(%USERPROFILE%\periscribe-agents). 그 아래 첫 경로 세그먼트 = container_id(웹 🐳 라벨).
⚠ 격리의 결: 이 구조는 파일시스템 + capability 수준. 컨테이너는 호스트와 같은 커널을 공유 → 커널 익스플로잇까지 막으려면 microVM(예: Firecracker). 네트워크/egress 차단은 범위 밖(인프라 계층에 둬야 강제 가능). 상세 CONTAINERS.md.
