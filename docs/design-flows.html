1. 컴포넌트 구조 (Context)

평문 키도 평문 payload도 중앙 서버를 통과하지 않는다. 암호화=Collector, 복호화=브라우저.

    CFG[("config.json<br/>device_token · 평문 DEK")]

  end
  subgraph SB["② Supabase 중앙 (운영자 소유)"]

    OK[("owner_keys<br/>공개키 + 봉인 개인키")]
    ING --> EV
    ING --> DV

  end
  subgraph WEB["③ 관리자 브라우저"]

2. 핵심 로직: DEK 생성 + 공개키 수신 ✅

per-device DEK는 머신에서 랜덤 생성, owner 공개키는 하트비트 응답으로 수신. 패스프레이즈는 컬렉터에 안 들어감.

sequenceDiagram
  autonumber
  participant COL as Collector
  participant ING as ingest (Edge Fn)
  participant DB as Postgres
  Note over COL: 설치 직후 config.dek="" · encrypt=true
  COL->>ING: beat() {device_token, machine}
  ING->>DB: devices 조회 (token_hash)
  ING->>DB: owner_keys.public_key 조회
  ING-->>COL: { enc:{public_key, kid}, backfill }
  alt public_key 없음 (관리자 미설정)
    Note over COL: 적재 보류 (store-and-forward)<br/>오프셋 전진 X · 다음 beat 재시도
  else public_key 수신
    COL->>COL: DEK = os.urandom(32) ← 로컬 랜덤
    COL->>COL: wrapped_dek = RSA-OAEP(public_key, DEK)
    COL->>COL: config.json 에 DEK 영속
    COL->>ING: 이후 beat/emit 마다 wrapped_dek 동봉(자가치유)
    ING->>DB: devices.wrapped_dek = wrapped_dek
  end

2.1 관리자 키 셋업 / 잠금해제 (웹) ✅

sequenceDiagram
  autonumber
  actor Admin as 관리자
  participant WEB as Web UI
  participant DB as Postgres
  alt owner_keys 없음 → 최초 셋업
    Admin->>WEB: 암호화 패스프레이즈 입력
    WEB->>WEB: RSA-OAEP 3072 키쌍 생성
    WEB->>WEB: KEK = PBKDF2(passphrase, salt, 600k)
    WEB->>WEB: wrapped_private_key = AES-GCM(KEK, 개인키)
    WEB->>WEB: 복구코드 생성 → recovery 봉인
    WEB->>DB: owner_keys insert
    WEB-->>Admin: 복구코드 1회 표시
  else owner_keys 있음 → 잠금 해제
    Admin->>WEB: 패스프레이즈 입력
    WEB->>DB: owner_keys 조회
    WEB->>WEB: KEK 유도 → 개인키 unwrap (실패=틀린 패스프레이즈)
    WEB->>WEB: 개인키 sessionStorage 보관
  end

3. 시나리오별 흐름

S1. 설치 → 로그 적재 → 조회 (정상 E2E) ✅

sequenceDiagram
  autonumber
  actor Admin as 관리자
  participant WEB as Web
  participant COL as Collector
  participant ING as ingest
  participant DB as Postgres
  Note over Admin,WEB: 선행 — 관리자 키 셋업(§2.1) 1회
  Admin->>WEB: 토큰 발급
  WEB->>DB: devices insert (token_hash)
  WEB-->>Admin: device_token (1회 표시)
  Admin->>COL: exe 실행 + 토큰 입력 (설치=토큰만)
  Note over COL: DEK 부트스트랩(§2)
  COL->>ING: beat
  ING-->>COL: enc.public_key
  COL->>COL: DEK 생성 → 봉인 → config 저장
  loop 폴링 0.4s
    COL->>COL: 새 줄 파싱 → 이벤트
    COL->>COL: payload/raw 암호화 · enc_version=1
    COL->>ING: emit [암호문] + wrapped_dek
    ING->>DB: events upsert(멱등) · devices 갱신
  end
  Note over Admin,WEB: 조회
  Admin->>WEB: 로그인 + 패스프레이즈
  WEB->>DB: owner_keys → 개인키 복원(세션)
  WEB->>DB: events 조회 + Realtime · devices.wrapped_dek
  WEB->>WEB: device DEK unwrap → payload 복호
  WEB-->>Admin: 평문 로그 표시 ✅ (키 없으면 🔒)

S2. 컬렉터 재시작 (DEK 유지) ✅

flowchart TD

  D --> F

S3. 암호화 키 대기 / 적재 보류 ✅

관리자 미설정·네트워크 단절 시 평문을 절대 올리지 않고 보류.

flowchart TD
  A["폴링 1회"] --> HB["heartbeat → enc.public_key 시도"]
  HB --> B{"encrypt=true?"}
  B -- "no" --> P["평문 적재(dry-run)"]
  B -- "yes" --> C{"DEK 보유?"}
  C -- "yes" --> E["암호화 적재"]
  C -- "no" --> F{"공개키 수신?"}
  F -- "no" --> H["적재 보류<br/>오프셋 유지"] --> A
  F -- "yes" --> G["DEK 생성·봉인·저장"] --> E
  E --> A
  P --> A

S4. Revoke (관리자 차단) ✅

sequenceDiagram
  autonumber
  actor Admin as 관리자
  participant WEB as Web
  participant DB as Postgres
  participant COL as Collector
  participant ING as ingest
  Admin->>WEB: 머신 관리 → revoke
  WEB->>DB: devices.revoked = true
  loop 다음 호출
    COL->>ING: emit / beat
    ING->>DB: devices 조회 (revoked=true)
    ING-->>COL: 401 revoked
    COL->>COL: SinkAuthError → 지수 백오프
  end
  Note over COL: 연속 10회 401 → 자가 종료
  Note over WEB,DB: 헬스바 숨김 · events/wrapped_dek 유지 → 과거 로그 복호 OK

S5. Uninstall (제거 신호 + 로컬 정리) ✅

sequenceDiagram
  autonumber
  actor User as 머신 사용자
  participant BAT as uninstall.bat
  participant ING as ingest
  participant DB as Postgres
  User->>BAT: 실행
  BAT->>ING: POST {device_token, uninstall:true}
  ING->>DB: uninstalled_at=now · revoked=true
  BAT->>BAT: 자동시작 해제 + 프로세스 종료
  BAT->>BAT: rmdir %LOCALAPPDATA%\Periscribe<br/>(config·평문DEK·checkpoint 삭제)
  Note over DB: "🗑 제거됨" · wrapped_dek 유지 → 과거 로그 복호 OK<br/>사라지는 건 로컬 평문 DEK뿐

S6. 디바이스 행 완전 삭제 (현재) ✅ — ⚠ 데이터 접근 손실

sequenceDiagram
  autonumber
  actor Admin as 관리자
  participant WEB as Web
  participant DB as Postgres
  Admin->>WEB: 머신 관리 → 삭제(완전)
  WEB->>DB: devices delete (행 제거)

S7. 삭제 후 재설치 — 현재 동작 (새 디바이스) ✅

sequenceDiagram
  autonumber
  actor Admin as 관리자
  participant WEB as Web
  participant COL2 as 재설치 Collector
  participant ING as ingest
  participant DB as Postgres
  Note over COL2: 삭제로 옛 config(평문 DEK) 소실
  Admin->>WEB: 새 토큰 발급
  WEB->>DB: devices insert (새 행 · 새 device_id)
  Admin->>COL2: 새 토큰 입력
  COL2->>ING: beat → enc.public_key
  COL2->>COL2: 새 DEK 생성·봉인
  COL2->>DB: 새 devices.wrapped_dek
  loop
    COL2->>DB: 새 events (새 device_id · 새 DEK)
  end
  Note over WEB,DB: 옛 행 남기면 옛 로그 복호 OK<br/>단 관리 목록엔 디바이스 2개(연속성 X)

S8. 디바이스 연속성 — machine_guid 자동 + DEK 키 히스토리 ✅

새 토큰 발급해 그 머신에 꽂으면 끝. 같은 머신(machine_guid)이면 ingest가 같은 디바이스로 자동 합침. 관리자 매칭 불필요.

sequenceDiagram
  autonumber
  actor Admin as 관리자
  participant WEB as Web
  participant COL2 as 재설치 Collector
  participant ING as ingest
  participant DB as Postgres
  Note over COL2: 삭제로 옛 config(평문 DEK) 소실 · machine_guid는 OS라 그대로
  Admin->>WEB: 새 토큰 발급(아무 거나)
  WEB->>DB: devices insert (토큰행 R2)
  Admin->>COL2: 새 토큰 입력 (같은 머신)
  COL2->>ING: beat {machine_guid=G}
  ING->>DB: (owner,G) 기존행 R1 발견 → R2 삭제 · R1.token_hash=새토큰
  ING-->>COL2: enc.public_key
  COL2->>COL2: 새 DEK 세대 (새 kid)
  COL2->>ING: wrapped_dek(새 kid)
  ING->>DB: R1.dek_keys[새 kid] = 봉인DEK (누적)
  loop
    COL2->>DB: 새 events (device_id=R1 · kid=새 kid)
  end
  Note over WEB,DB: 옛 이벤트→dek_keys[옛 kid] · 새 이벤트→dek_keys[새 kid]<br/>관리 목록 디바이스 1개(연속) ✅ · 관리자 revoke만 차단(제거됨은 되살림)

4. 디바이스 수명주기 상태도

stateDiagram-v2
  [*] --> issued: 토큰 발급
  issued: 발급됨(미설치)
  online: 온라인
  stale: 대기(만료)
  revoked: revoked
  removed: 제거됨
  issued --> online: 설치+하트비트
  online --> stale: 75s 무응답
  stale --> online: 하트비트
  online --> revoked: 관리자 revoke
  stale --> revoked: 관리자 revoke
  online --> removed: uninstall 신호
  stale --> removed: uninstall 신호
  online --> online: 재설치(같은 machine_guid)→같은 행 자동 연결
  removed --> online: 재설치 → 되살림(사용자 제거는 차단 안 함)
  revoked --> [*]: 완전 삭제(⚠복호 손실)
  removed --> [*]: 완전 삭제
  note right of revoked: 관리자 revoke만 차단(제거됨은 되살림)

5. 데이터 모델 (ER)

erDiagram
  auth_users ||--o{ devices : "owns"
  auth_users ||--|| owner_keys : "has"
  auth_users ||--o{ events : "owns"
  devices ||--o{ events : "device_id(FK없음)"
  owner_keys {
    uuid owner_id PK
    text public_key "RSA 공개키(SPKI)"
    jsonb wrapped_private_key "KEK로 봉인한 개인키"
    jsonb wrapped_private_key_recovery "복구코드 봉인"
    jsonb kdf_params "salt·iterations"
  }
  devices {
    uuid id PK
    uuid owner_id FK
    text token_hash "sha256(token)"
    bool revoked
    timestamptz uninstalled_at
    text wrapped_dek "공개키로 봉인한 DEK"
    int dek_kid
  }
  events {
    text event_id PK "멱등키"
    uuid owner_id
    uuid device_id
    int enc_version "0=평문/1=암호문"
    jsonb payload "암호문 envelope"
    jsonb raw
  }

6. 암호화 경계 요약

자산위치운영자 접근
평문 payloadCollector 메모리 · 브라우저(복호 후)❌
평문 DEK머신 config.json❌
봉인 DEKdevices.wrapped_dek⭕ 암호문(개인키 없으면 무용)
owner 개인키브라우저(세션) / DB(봉인본)❌ / ⭕ 봉인본
owner 공개키DB · 응답⭕ 비밀 아님
패스프레이즈사람 머릿속❌
메타데이터events(평문)⭕
⚠ 한계: 복호화 웹 JS를 운영자가 서빙 → 악의적 운영자의 복호화-시점 키 탈취는 못 막음(at-rest 제로지식까지가 보장 범위). 상세 docs/E2EE-DESIGN.md §7.
