⌖ Periscribe — 사용 설명서

AI 에이전트(Claude Code) 사용을 기록·통제·검토하는 시스템. 이 문서는 설치부터 운영까지를 다룹니다.

개요·구성설치컬렉터 에이전트(컨테이너)프록시·통제웹 대시보드 보안제거

1. 개요 · 구성

Periscribe 는 역할이 다른 3개의 독립 프로그램으로 구성됩니다. 필요한 것만 설치합니다.

프로그램역할설치 위치
periscribe 컬렉터이 PC의 AI 사용 기록을 수집해 서버로 전송. 트레이 상주 + 프록시 라우팅 토글%LOCALAPPDATA%\Programs\Periscribe
periscribe-proxy 프록시 서버Claude↔Anthropic 트래픽을 가로채 기록·차단·통제. 단독 실행(중앙 서버에도 이것만)…\Programs\Periscribe Proxy
periscribe-agent 에이전트 런처Docker 컨테이너에 Claude Code 를 격리 실행. Docker 필요…\Programs\Periscribe Agent

데이터 흐름

[Claude Code] --(transcript/프록시)--> [컬렉터] --E2EE 암호화--> [Edge Function] --> [Supabase] <-- [웹 대시보드(관리자 복호)]

수집 데이터의 내용(프롬프트·응답·작업)은 종단간 암호화되어 저장되고, 복호화 키를 가진 관리자만 웹에서 열람합니다. 메타데이터(머신·세션·시각·동작종류)는 인덱싱용으로 평문입니다.

데이터(설정·인증서·로그)는 %LOCALAPPDATA%\Periscribe 에 별도 보관됩니다(프로그램 폴더와 분리 → 재설치에도 보존, 제거 시 삭제).

2. 설치

관리자에게 받은 디바이스 토큰이 필요합니다(웹 관리자가 발급). 무관리자(admin 권한 불필요)로 설치됩니다.

  1. 컬렉터: periscribe-setup.exe 실행 → 설치 → 첫 실행 창에 토큰 붙여넣기 → 끝. 부팅 시 자동 시작.
  2. 프록시 서버(선택): periscribe-proxy-setup.exe 실행 → 설치. 시작 메뉴에서 실행.
  3. 에이전트(선택, Docker 필요): periscribe-agent-setup.exe 실행 → 설치.
실행 시 임시폴더 추출이 없는 onedir 구조라 빠르고 안정적입니다. 다운로드: 웹 대시보드 또는 관리자 배포 링크.

3. 컬렉터 (수집)

3.1 트레이 컨트롤 패널

설치 후 periscribe.exe(또는 시작 메뉴 Periscribe)를 실행하면 컨트롤 패널이 뜹니다.

  • 머신 이름 · 수집 상태 표시
  • 🛰 프록시 라우팅 ON/OFF 토글 — 이 PC의 Claude 를 프록시로 보낼지 직결로 둘지
  • 창 닫기(X) → 시스템 트레이로 최소화. 트레이 아이콘 우클릭 → 열기/종료. 수집은 백그라운드로 계속

3.2 수집 동작

컬렉터는 ~/.claude/projects(및 컨테이너 루트)의 transcript 와 spool 을 0.4초 주기로 따라가며 새 줄만 정규화·암호화해 전송합니다. 오프셋 체크포인트로 재시작에도 손실·중복 없이 재개합니다(event_id 멱등).

3.3 과거 기록 백필

기본은 설치 시점부터(EOF) 수집합니다. 과거 전체가 필요하면 웹 세션 관리 → 과거 백필 버튼으로 그 세션을 처음부터 재적재합니다.

3.4 OS 쉘/프로세스 감사 (선택, 관리자 1회)

transcript 비의존으로 Claude 가 실제 실행한 프로세스를 OS 레벨(Sysmon)로 보강합니다. 관리자 권한으로 periscribe.exe audit-setup 1회 → 이후 컬렉터가 Sysmon 이벤트에서 Claude 서브트리만 골라 수집(웹 🐚 OS).

4. 에이전트 (컨테이너 격리)

VS Code 없이 Claude Code 를 Docker 컨테이너에 격리 실행합니다. 컨테이너 레벨(커널)에서 강제되는 정책이라 에이전트가 끌 수 없습니다.

periscribe-agent <작업폴더> --name <박스이름> [--shell] [--proxy] [--policy <json>]
옵션설명
<작업폴더>컨테이너 /workspace 로 마운트할 폴더(기본: 현재)
--name박스 이름 = 웹에서 🐳<이름> 으로 구분
--shellclaude 대신 bash 진입
--proxy컨테이너 Claude 를 호스트 프록시로 라우팅(로깅·통제 적용) — 아래 5장 참고
--policy제어 정책 JSON 경로(생략 시 박스별 자동 생성)

4.1 컨테이너 제어 정책

호스트의 정책 JSON(%LOCALAPPDATA%\Periscribe\policies\<박스>.json)을 편집하면 다음 실행부터 docker 플래그로 적용됩니다(재빌드 불필요).

{
  "workspace_writable": true,   // false → 작업폴더 읽기전용
  "network": true,              // false → --network=none(망 차단)
  "read_only_rootfs": false,    // true → 루트FS 읽기전용
  "no_new_privileges": false,
  "drop_all_capabilities": true,
  "memory": null,  "cpus": null,  "pids": null   // 자원 한도
}

컨테이너의 ~/.claude 는 호스트 <container_root>/<박스> 에 바인드되어 ① 로그인 토큰 영속 ② transcript 를 컬렉터가 자동 수집합니다.

5. 프록시 · 통제

프록시 서버가 Claude↔Anthropic 사이에 앉아 트래픽을 기록하고 정책으로 통제합니다. 자체 CA 로 TLS 를 복호화하므로 평문 검사가 가능합니다(서버 내부에서만, 서버↔Anthropic 은 정상 TLS).

5.1 호스트(이 PC)에서 쓰기

  1. periscribe-proxy.exe 실행 → 프록시 서버 기동(자체 CA/인증서 자동 생성)
  2. 컬렉터 트레이 패널에서 프록시 켜기 → 이 PC의 Claude 트래픽이 프록시 경유(웹 🛰 API)

5.2 컨테이너에서 쓰기 (--proxy)

컨테이너는 호스트와 격리돼 있어 별도 설정이 필요합니다.

  1. %LOCALAPPDATA%\Periscribe\config.json 에 "api_proxy_bind": "0.0.0.0" 추가 → 프록시 서버 재실행(컨테이너가 닿게 전 인터페이스로 listen)
  2. periscribe-agent --proxy <작업폴더> → 컨테이너에 프록시 주소(host.docker.internal)+CA 가 주입되어 통제 적용
0.0.0.0 바인드는 프록시 포트를 LAN 에 노출합니다(접속하려면 우리 CA 신뢰 필요). 신뢰 네트워크에서만 사용하세요.

5.3 통제 정책 (proxy-policy.json)

%LOCALAPPDATA%\Periscribe\proxy-policy.json 을 편집하면 매 요청마다 즉시 반영(핫리로드, 재시작 불필요).

{
  "enabled": true,
  "block_patterns": ["비밀번호", "aaaa"],      // 프롬프트에 매치 시 차단
  "block_message": "취소",                      // 차단 시 프록시가 대신 응답할 말
  "redact_patterns": ["TOKEN=\\S+"],            // 전송 전 마스킹([REDACTED])
  "inject_system": "안전 가이드라인…",          // 시스템 프롬프트에 가드레일 주입
  "gate_tool_use": true,                        // 응답측 위험 도구 차단 ON
  "tool_block_patterns": ["\\brm\\b", "Remove-Item"],
  "tool_block_message": "파일 삭제 - 차단"
}
통제동작
요청 차단신규 프롬프트가 block_patterns 매치 → Anthropic 미전송, 프록시가 block_message 로 직접 응답(에러 아님, 세션 유지). 히스토리는 재차단 안 함
레닥션전송 본문에서 redact_patterns 마스킹 → 민감정보가 Anthropic 으로 안 나감
시스템 주입inject_system 가드레일을 system 프롬프트에 append
도구 게이팅응답의 위험 tool_use(예: rm)가 tool_block_patterns 매치 → 도구를 드롭하고 tool_block_message 표시 → Claude 가 실행할 도구를 못 받아 차단됨

6. 웹 대시보드

관리자가 로그인해 조직 전체의 AI 활동을 실시간으로 봅니다.

6.1 머신 추가 (토큰 발급)

⚙ 머신 관리 → 머신 이름 입력 → + 토큰 발급(한 번만 표시). 이 토큰을 해당 PC 설치 시 입력. 이탈/분실 시 revoke → 즉시 무효.

6.2 세션 피드 · 출처 탭

이벤트가 실시간으로 흐릅니다. 상단 출처 탭(전체 / 📝 Transcript / 🛰 API / 🐚 OS) 으로 로깅 경로별로 나눠 봅니다(같은 대화는 transcript·API 가 한 세션으로 합쳐짐).

6.3 위험 분류 · 통제 현황

  • 위험 분류: 도구·명령을 자동 분류(파괴/권한/자격증명/네트워크 등)하여 심각도(🔴크리티컬/⚠경고)로 필터.
  • 통제 현황 KPI(헬스바 아래): 🛡 차단 · ⚠ 위험동작 · 🖥 머신 · 💬 세션 집계. 칩을 누르면 해당 필터 적용. "🛡 차단만" 토글로 프록시가 실제 차단한 동작만 봅니다.

6.4 E2EE 복호

최초 로그인 시 패스프레이즈로 개인키를 복원합니다(브라우저에서만). 이후 이벤트 내용이 자동 복호되어 표시됩니다. 서버에는 암호문만 있어 운영자도 내용을 못 봅니다(호스팅형 기준).

7. 보안 모델

  • 디바이스 토큰: 각 PC는 자기 토큰만 보유 → 유출돼도 그 머신 적재만 가능, 읽기 불가.
  • RLS: owner_id = auth.uid() → 관리자는 자기 소유 데이터만 조회.
  • E2EE: 내용은 per-device DEK(AES-256-GCM)로 암호화, DEK 는 관리자 공개키로 봉인. 개인키는 서버를 거치지 않음.
  • 프록시 CA: localhost/host.docker.internal 한정 리프만 서명 가능. 개인키는 그 PC 로컬에만.

8. 제거

설정 → 앱(프로그램 추가/제거)에서 각각 제거합니다. 컬렉터 제거 시 서버에 제거 신호(자동 revoke) + 자동시작 해제 + 데이터 폴더 삭제가 수행됩니다.
